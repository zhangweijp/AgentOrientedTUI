## 先用 IDE 说明：为什么“打不开新页”还有需要定义的含义

假设 `files` 已正常工作，Agent 希望打开一个很大的 `test.txt`。直觉上可以说“新页面太大，打开失败”；但一个系统合同还必须回答：原来的 `files` 是否继续可用，文件读取是否已经发生，页面内部状态是否已经改变，哪些结果可以撤回，以及 Tool 收据该怎样准确表达这些事实。

如果把所有情况都叫“打开失败”，Agent 可能无法知道现在该继续工作、关闭页面，还是等待恢复；如果框架擅自把 App 已发生的业务操作也当成能回滚，又会超出自己的职责。这个例子只说明要解决的问题，**不预先决定旧页面一定保留、整个候选必须回滚，或所有失败采用相同分类**。

这里必须把“成功观察包含全部已打开页面”这一已定目标，与“未成功接纳新页时怎样维护状态”这一未定机制分开。本次补例子与比较不会改变暂缓决定。

## 当前比较的是推进方式，不替用户选开页机制

| 处理方式 | 好处 | 代价与风险 | 现在的判断 |
| --- | --- | --- | --- |
| A. 立即针对已复现分支做局部修补 | 可以很快改变已知症状；范围看似小 | 若总体失败语义未定，可能把一个临时结果固化为合同；局部通过不能证明其他准入与恢复路径合理 | 不列入当前任务；未来若有独立、明确授权的阻塞性修复，再按其范围处理 |
| B. 现在完整设计通用开页事务、回滚与导航协议 | 可同时讨论生命周期与失败语义 | 当前需求未充分确定；容易把业务补偿、DOM 生命周期和 Host 预算一起装进 Core；与明确暂缓决定冲突 | 不采用 |
| C. 固定现有目标，保存最小复现和待答问题，等恢复议题后集中选择 | 事实不会丢失；其他模块可继续明确各自职责；不会偷偷制造新兼容承诺 | 已知机制仍有需要澄清之处，文档必须诚实说明；不能把问题标为已修复 | **按用户决定采用此推进方式** |

这张表不是三种开页实现的评审。具体候选机制只有在本议题恢复后，才能基于同一组失败例子、责任边界与可验证结果比较。现在只列出历史候选名称，不继续为其设计状态机或 API。

从长期主义看，过早固定一个跨层事务合同比晚一些选择更难撤回；从 Minimalist 看，当前该做的是保留足够重启讨论的事实与边界，而非预建通用事务平台。暂缓也不意味着后续 SDK / Runtime 重构可以悄悄改变当前开页行为：有关改动仍须显式说明影响，不能借其他议题替本议题作决定。

## 暂停的候选方案

- 统一所有 opening 容量错误的拒绝分类；
- 先构造候选页面集合再接纳；
- 改写 `prepareOpeningProjection(update, revert)`；
- 移除或重构 Core 的 `restore/retainViews`；
- 导航恢复、页面生命周期以及后台变化的组合语义。

这些都仍是历史讨论中的候选，**不是 accepted 决策**。

## 仍然有效的既有产品约束

暂停细节设计不撤销已有目标：成功观察包含全部已打开页面；不能通过静默隐藏已打开页面来绕过容量限制；工具能力随页面与实例条件暴露；App 自己负责业务写入与业务恢复。

“如何满足这些约束”留待本议题恢复后统一决定，不由其他改造顺带固定。

## 评审补充：先把现有失败分支说准确

[Review 10](REVIEW-2026-11-18.md#review-10) 对作者措辞的提醒成立。日常语言中的“内容太大”可以落在不同验证边界，不能由这几个字推导导航必定恢复：

| 当前路径的例子 | 已有机制能证明什么 | 作者说明应如何限定 |
| --- | --- | --- |
| 命中 coordinator 后段、满足既定 opening 条件的 `OBSERVATION_CAPACITY` | 可以得到该专用拒绝结果；Preact 按相应分支执行作者提供的 revert | 把可恢复的前提写成具体结果与条件，不能泛指所有容量相关失败 |
| 前段快照验证返回 `SNAPSHOT_SERIALIZATION_ERROR` 等错误 | 在进入专用 opening 容量分支前即失败；不能套用后段拒绝的保证 | 查看实际错误、投影健康及业务结果；不承诺旧页始终可操作或业务已回滚 |
| App 投影合规，但完整模型请求超预算 | 属于 Host 的整轮 Messages / Tools / 输出预留检查 | 不把单 App JSON 限额等同于整轮 token 预算 |

这与 [`coordinator.prepare`](../../runtime/src/core/projection/coordinator.ts) 的检查顺序一致。建议在当前 SDK 作者说明中用这一对正反例限定“容量拒绝时恢复导航”的含义；本轮先把判断写入本议题，不改 opening API、恢复状态机或既有失败行为。历史 513 KiB 复现不因此次源码核对就变成本轮重跑结果。
