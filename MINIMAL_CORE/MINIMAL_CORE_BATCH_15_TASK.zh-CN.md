# Batch 15 · 同一个工具怎样接收一个计划、整份列表或几个名字

本批承接通过独立复核的 Batch 14 修订。一个名字可以指向一份计划，也可以指向一整份计划列表。模型另外还可以逐个指定几个计划的名字。在后两种情况下，业务函数都可能拿到一组计划，但模型提供的参数和框架要检查的对象不同。总计划 U2 要求把这几种写法，以及可省略的引用，放到同一套普通工具声明下。[总计划 U0–U2](MINIMAL_CORE_REFACTOR_PLAN.zh-CN.md)

**范围限于合同试件。** 从签收的 Batch 14 实际输入和累计补丁起步。可改的副本限于 SDK 的 `src/tools/view-type-tool.ts`、`src/tools/typebox-schema.ts` 和 Runtime 的 `src/core/tool/ordinary-parameter-contract.ts`，另可写本批独立样例。以一个 Planning 工具完成主要验证，让它接收当前计划、用于对照的整份列表、几个逐项指定的计划名，以及一项普通备注。不要为不同组合新建工具类别、注册中心或第二套解析器。共享项目、SRT 工作树和历史证据只读。

**准出条件**

1. 作者只写一份工具参数声明。单对象和整份列表各接收一个字符串，逐项选择接收字符串数组，备注仍是普通字符串。至少一个真实函数在严格类型检查下消费相应只读业务值。可选的单对象、整份列表和逐项选择分别验证“没有提供”和“提供了错误值”。
2. 在另一进程读回 JSON。用同一工具、同一字段证明“一个列表名字”和“一组对象名字”的合同身份不同，必填与可选、不同业务种类也能区分。给出原始模型参数和业务参数各一份可读样本，并标清程序在哪里判断该字段的含义。
3. 用已封存的真实计划、列表和元素覆盖有效输入，以及列表与对象混淆、其中一项无效、必填缺省、可选但传错、普通备注恰好与引用同名。组合中任一项失败时，整组返回失败。验证展开后按整组输入执行原有容量限制，包括同一大计划重复出现在两个参数里的情况。清楚区分名字、已取得的数据与可执行资格。
4. 从冻结的旧包和既有普通注册入口验证新声明会明确拒绝，工厂与业务函数均无进入。独立复跑须保留原普通参数测试、Batch 14 的单对象/列表、同形类型及声明类型一致性。交回最小增量、严格类型正反例、跨进程输入输出和可逆补丁。若最小改动无法表达某个组合，请保留能定位到字段的第一个失败，说明是声明、导出还是编译层所限。

当前真实 Planning 样本的对象发布标签为 `unknown`。本批只检查声明与已取得值，不得从字段形状推断发布标签或执行授权。正式 helper 名称、共享包迁移、观察生命周期、Worker 协商和线上执行不在本批范围。完成后统一列出定稿作者合同仍需上级决定的事项。

**给执行 Codex 的 Prompt**  
在隔离副本用一个真实 Planning 类型的工具覆盖“一个对象名字、一个列表名字、多个对象名字、可省略引用及普通备注”。沿用 Batch 14 已签收的单一声明，交出模型在每种情况下传什么、业务函数拿到什么、错误或超限在何处被挡住的可复跑证据。保留旧包和普通工具的行为，按上述四项准出。遇到必须改变共享 API、在线授权或 Worker 协议的地方，停在最小证据处，交 READY_FOR_REVIEW。
