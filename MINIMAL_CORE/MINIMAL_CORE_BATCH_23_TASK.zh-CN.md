# Batch 23：让 Agent 按页面上的名字正确使用 Ref

**AUTHORIZED_FOR_IMPLEMENTATION_AND_REVIEWED_APPLICATION。** 所有者于 2026-11-06 明确“文件是不需要 Ref 的，因为文件路径的作用就是 Ref，我们不需要再使用 Ref 强包装一层”，在听取现有呈现、传参及系统说明不一致的问题后要求“没问题，继续推进吧”。本批只修正与该边界相冲突的 Agent 使用说明。候选经技术负责人独立批准后，执行者可将精确修正应用到共享树并复验；不包含 B22 新协议的共享采用、发布、提交或最终 Semantic 验收。

## 要改变的实际问题

当前 `runtime/src/adapters/system-instruction.ts` 教 Agent 使用 `(content)[type:ref_id]`，实际 SDK 输出 `[content](完整引用名字)`；示例调用还省略类型前缀。另有“对象参数都应传 Ref”和“数据对象替代普通 ID”的全局说法。它们会误导正常路径、普通 JSON 参数及显式 Ref 的选择。

只按现有实际合同修正：页面 Ref 使用 SDK 已有格式；Agent 复制完整名字，包括已有类型前缀和下标；只有显式要求 Ref 的参数使用引用，普通参数遵守自身 Schema。文件直接传路径，不要求额外注册/包装 Ref。Ref 不自动展开全部数据到模型上下文，也不替代 App 的业务前置条件。不要把任意 Markdown 链接自动解释为可用 Ref，不新增解析器、自动推断或默认转换。
