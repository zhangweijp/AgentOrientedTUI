## 准出条件

1. **能从原件重建同一组合。** 核对签收对象和三份补丁的身份、顺序、正向及逆向检查，记录九个修改文件的前后指纹与五个上游差异。基于完整的签收源码准备包应有的文档、声明与运行文件。分别构建原始 M4.3 和组合，在私有目录生成两者的 SDK/Runtime tar，保存实际使用的包指纹和条目。找得到签收 tar 时核对输入原件及实质差异，包装时间等差异单列。复跑只需固定 Git 对象、仓内既有材料和所列本地依赖。
2. **从包的消费者复验关闭故障。** 在消费目录从 tar 实际装入 SDK/Runtime，记录公开导入和 Worker 的实际落点，防止错误解析共享 dist。用签收的关闭探针让 App 自己的 cleanup 抛错。在旧 M4.2 组合复现原工具继续进入业务，在原始 M4.3 和新组合验证旧业务进入零次、健康 App 与同位置重开的 App 可用、最后工具和页面释放。区分业务主动抛出的错误、旧工具的拒绝和测试环境故障；旧版预期红灯保留原件。
3. **从同样装包的入口验证引用。** 严格编译真实 Planning 页面和必要试件，通过默认 Source 取页面可见的名字，再由 Node Worker 核对收到的完整计划、类型及执行次数。至少验证正确计划、同形的其他类型、把整份列表当单个计划、跨页不可见及 Context 释放后重用。前置拒绝要有定位与业务零进入。对照原始 M4.3，让 `itemType: 'Plan'` 恢复传递产生的差异可见。另通过该套包已有的普通工具入口执行一次普通参数工具，并交一份已签收的新 Ref 参数声明给同一条普通注册链，记录第一次拒绝的位置、代码和工厂/业务进入次数。报告把已经可用的单引用路径、隔离合同支持的列表/多选、普通注册目前能执行的范围分开。
4. **明确这一批能交给下一位什么。** 提供一键私有复跑、实际包解析记录、可复查的正反例、上一版本首次失败和新的独立结果。只计本批实跑。SRT 原作者试验公开材料合规为 6/9，门槛为 8/9；本批不启动新模型试验。引用命名范围、旧数据保留、公开作者接口选择和所有者最终 Semantic 验收各按原有归属处理。发现真实边界后给出下一项最小作者任务。
