# 下一批：串行刷新与新旧观察交接的只读准备

2026-11-08。**本任务授权只读盘点、最小方案和验证设计，不授权生产改动、公开 API 采用或最终 Semantic 验收。** 本任务细化既有 SRT-04／05，不另设产品目标或平行 TODO 索引。D3 历史迁移仍取消。

## 目标与责任

Agent 下一轮应看到应用已经提交的变化；同一正式消费会话采用新观察后，旧观察的调用／Ref 解析资格应按明确合同失效，框架不再持有无用的旧数据。应用业务状态和仍被新快照使用的共享对象不能被错误删除。GUI 预览和诊断读取不替 Agent 切换当前观察。

执行方负责读取和提出方案；Minimal Core 负责人独立核对。两方均不修改生产候选。大范围架构、产品语义或重大公开 API 差异必须形成具体方案后交项目所有者决定，既有目标不重复征求确认。

## 范围与交付

1. 以已批准 SDK 工具增量候选 `.tmp/typescript-sdk-tooling-20261108/candidate-r01` 为技术基线；另外只读核对当前共享工作树的相关链路。记录实际读到的少量相关文件身份和差异，不能用旧 HEAD 或候选状态冒充共享现状。
2. 从 Driver 捕获／采用／替换／释放 Context，追到适配 Source、现有 Scope owner、Observation／binding、Snapshot Store 与 Ref 持有关系。说明各对象由谁持有，何时获得调用资格，何时失去资格，何时不再持有 payload。
3. 区分业务完成、投影提交、观察捕获、正式采用四个时点。查明现有 flush 边界；不能以固定 sleep、后台业务结束或重读磁盘作为提交完成保证。
4. 说明重叠 Context、捕获成功但未采用、捕获失败、单 App 投影错误、GUI 预览、同名重开、在途调用和晚响应的行为。新资格撤销不能伪造在途副作用已经撤销，也不能自动重做结果未知的业务。
5. 检查注册所有权、重复 Ref 名及旧 cleanup 误删后继注册，明确哪些属于本次交接必须保证、哪些需要独立修复；不默默扩大实施范围。
6. 给一个首选最小方案和必要的真实备选，优先复用现有 owner／采用边界。逐项说明删除什么重复职责、行为由谁保留、作者是否增加概念；没有理由时不新增 manager、兼容层、App ACK 或新调度器。
7. 形成精确后续补丁范围、公开合同差异、验证矩阵和 Codex Prompt。说明纯 Core、普通 TypeScript、SDK Worker、Source／Driver 消费各能证明什么；正常包消费不能由源码 alias 替代。

本批不运行 Host、GUI、真实模型，不读取或改写私人手测状态，不开展并发、配额／预算或通用回收策略重设计，不改 App 业务状态、文件权限或历史消息。

## 只读准出条件

- 每项现状结论都有实际文件和调用顺序依据；目标、当前行为、建议和历史证据明确分开。
- 每个状态／引用有唯一可说明的 owner；资格撤销与实际框架引用释放分别有观测点，不以 GC 或 RSS 代替证据。
- 测试矩阵至少覆盖：已提交变化下一轮可见；采用新观察后旧调用／Ref 拒绝；未采用的诊断捕获不撤销当前资格；失败切换保留明确有效状态；关闭／同名重开不串对象；旧专属引用退出而共享／App 自有状态保留；在途调用结算及晚响应；两个 Producer 相同结果。
- 任何会改变现行公共支持的部分明确列出，不将所有者尚未决定的机制写成已批准实现。
- 独立评审能据交付给出 APPROVED 或 CHANGES_REQUESTED，并直接形成下一条具体实施或决策任务。
