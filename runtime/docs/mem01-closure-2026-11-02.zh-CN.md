## 定位依据与最小修复

首先用原交付包重跑未经修改的 `demo-apps/aotui-ide/tests/scoped-ide-performance.mjs`。第 1 轮在 `cycle-2-close` 采样到 **1034.28 MiB**，超过 1024 MiB，进程退出码为 1；因此没有执行后两轮。该轮的功能、延迟和资源关闭检查已经通过，60 次文件循环的内存中位数增量为 18.25 MiB，记录到的 44 个子进程和 11 个进程组全部退出。

峰值由约 419.8 MiB 的主进程和 614.5 MiB 的 LSP 子进程组成。真实进程参数显示，默认配置启动了语言服务器、一个 `partialSemantic` tsserver、一个完整 tsserver，以及 `typingsInstaller`。额外的语法服务器在这次峰值中占约 194 MiB。主进程 RSS 同时包含 Worker，不能把主线程 `heapUsed` 当成整个 Runtime 的内存。

已安装的 typescript-language-server 5.1.3 支持 `initializationOptions.tsserver.useSyntaxServer: 'never'`。该选项让一个完整 `main` tsserver 处理语法与语义请求，避免额外启动语法服务器。它不关闭 Automatic Type Acquisition（ATA）。先用同一基线包做临时配置对照，原三轮测试峰值为 885.55、914.91、935.67 MiB，均通过；随后才实施正式改动。

正式生产改动只有 `demo-apps/aotui-ide/src/core/lsp/server.ts` 中的一行配置：

```ts
tsserver: { useSyntaxServer: 'never' },
```

自定义服务器配置、支持版本判定、进程组归属和关闭验收保持原合同。最终新包的真实进程探针确认：语言服务器、一个完整 tsserver 和 ATA 进程存在，没有 `partialSemantic` 进程，关闭成功。

这是默认 IDE 资源配置与预算不匹配的修复。当前证据没有显示关闭后遗留 LSP 进程，也没有证明 Runtime 存在无界泄漏。只读审查发现的 Core 临时复制优化候选未进入本次修改，避免凭峰值超限扩大内核改造。

## 未改变的验收条件

- 环境：本机 macOS，Node v24.15.0，typescript-language-server 5.1.3，TypeScript 5.9.3。
- 原脚本：65 个 TypeScript 文件，每文件 220 行、19140 字节；小规模、8 文件、64 文件边界及第 65 个文件拒绝；完整 View 内容按每页 4 个 View 遍历。
- 每次运行 3 轮；每项采样包含 2 次预热和 10 次正式样本；每轮 60 次文件打开／查询／关闭、10 次 App 重开／查询／关闭。
- 整个自有进程树峰值 RSS 不超过 **1024 MiB**；60 次循环最后 20 个样本中位数减去最初 20 个样本中位数不超过 **128 MiB**。
- 保留真实 LSP、延迟门槛、Core 容量限制及每个已记录子进程和进程组的退出断言。没有缩小数据、提高门槛或强制 GC。
