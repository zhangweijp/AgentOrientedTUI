# @aotui/core

Core provides the shared App factory contract and the executable rules for complete View projections, Tool parameters, Ref values, observations and calls. Use `@aotui/sdk` to author an App and `@aotui/runtime` to host it in a managed Worker. Both consume this package.

For a custom host, `createSnapshotCore` owns an App instance's committed snapshots. Use `SemanticProjectionCoordinator` to prepare and publish complete frames, then use `createAppInteraction` with an explicit policy and execution binding. Prepare an observation before sending it to the model, adopt the one actually sent, and dispatch using its original observation and invocation IDs. Release the observation when the turn ends. The execution port still checks that the selected View and Tool binding are live. The example ships in `@aotui/core`. Copy it into an ESM project for compilation with TypeScript. [Complete Core example](examples/public-core.ts)

When assembling a Preact App directly, supply `RuntimeContext.readPreparedProjection: () => projection.readPreparedProjection()` using the same coordinator as `publishFrame`. This reads the local version of the App's healthy accepted frame without publishing. Plain TypeScript factories supply complete candidate frames through `publishFrame`.

Tool and Ref value declarations are bounded plain JSON Schema 2020-12 objects in the supported AOTUI profile. Declare a fixed tuple with `prefixItems`, `items: false` and a matching `minItems`. An empty tuple omits `prefixItems`. Core compiles admitted rules with `typebox/schema` from TypeBox 1.4.3 and reuses them for calls. Model addresses resolve against the original observation before the resolved JSON undergoes the same business validation.

Core's public types work with the ES2022 standard library. It uses platform-standard encoding, cancellation and timers when running the semantic operations. For optional persistence, `createStateSession` accepts a supplied `StateStorage` and operates on explicit addresses through `load`, `save` and `remove`. Work at the same address follows admission order. A flush captures queued and active mutations and the bounded settled results retained for each address. It waits for those results. The managed Runtime owns namespaces, Workers, transport and concrete storage backends. `@aotui/core/internal` connects the matching SDK and Runtime implementation.
